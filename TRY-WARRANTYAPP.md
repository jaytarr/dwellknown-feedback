# Try WarrantyApp on Android

This early-access build tests the first complete WarrantyApp journey. It uses
shared test data, so do not enter real home, product, warranty, receipt, photo,
document, password, or payment information.

## Install and sign in

1. On an Android phone, open [Install WarrantyApp](https://expo.dev/accounts/cre8worlds-team/projects/cre8worlds/builds/61a22033-7c7e-4e55-97b3-e70ec47b8ec0).
2. Download and install the Android build. If Android asks whether to allow an
   install from the browser, allow it for this install only.
3. Open WarrantyApp.
4. In **Tester access**, enter the test email and test password supplied to you
   privately, then select **Sign in**. These are sign-in credentials for the
   shared test account; they are not app settings.

## Complete the first journey

1. Open **Records**, then select **Add a record**.
2. Choose **Purchased item**, then **Continue**.
3. Enter `Tester record` followed by the current date and time as the record
   name, choose **Small appliance**, then select **Continue**.
4. Choose **Personal item / moves with me**, leave the optional fields empty,
   then select **Continue**.
5. Review the details and select **Save record**.
6. Confirm the new record appears in **Records**.
7. Fully close WarrantyApp, reopen it, and confirm the same record is still in
   **Records**.

The visible success result is the same named record after the app has been
closed and reopened.

## Send feedback

In WarrantyApp, open **Account** → **Support** → **Send feedback**, or open
[Send WarrantyApp feedback](https://github.com/jaytarr/warrantyapp-feedback/issues/new?template=tester-feedback.yml).

Tell us approximately when the problem occurred, what you tried, and what you
saw. Reports are public and require a GitHub sign-in. Do not include
credentials, sign-in codes, home addresses, record contents, photos, documents,
receipts, or payment information. The project team already knows which build
was supplied and will correlate that information internally.

# Essayer WarrantyApp sur Android

Cette version d’accès anticipé sert à tester le premier parcours complet de
WarrantyApp. Elle utilise des données de test partagées. N’entrez aucun
renseignement réel sur un domicile, un produit ou une garantie, ni aucun reçu,
photo, document, mot de passe ou renseignement de paiement.

## Installer l’application et ouvrir une session

1. Sur un téléphone Android, ouvrez [Installer WarrantyApp](https://expo.dev/accounts/cre8worlds-team/projects/cre8worlds/builds/61a22033-7c7e-4e55-97b3-e70ec47b8ec0).
2. Téléchargez et installez l’application. Si Android demande l’autorisation
   d’installer à partir du navigateur, accordez-la uniquement pour cette
   installation.
3. Ouvrez WarrantyApp.
4. Dans **Accès pour les testeurs**, entrez le courriel et le mot de passe de
   test qui vous ont été transmis en privé, puis sélectionnez **Ouvrir une
   session**. Il s’agit des identifiants du compte de test partagé, et non de
   paramètres de l’application.

## Effectuer le premier parcours

1. Ouvrez **Dossiers**, puis sélectionnez **Ajouter un dossier**.
2. Choisissez **Article acheté**, puis **Continuer**.
3. Entrez `Dossier test` suivi de la date et de l’heure comme nom du dossier,
   choisissez **Petit électroménager**, puis sélectionnez **Continuer**.
4. Choisissez **Article personnel que j’emporte avec moi**, laissez les champs
   facultatifs vides, puis sélectionnez **Continuer**.
5. Vérifiez les renseignements et sélectionnez **Enregistrer le dossier**.
6. Confirmez que le nouveau dossier apparaît dans **Dossiers**.
7. Fermez complètement WarrantyApp, rouvrez l’application et confirmez que le
   même dossier apparaît toujours dans **Dossiers**.

Le résultat visible attendu est le même dossier nommé après la fermeture et la
réouverture de l’application.

## Envoyer des commentaires

Dans WarrantyApp, ouvrez **Compte** → **Soutien** → **Envoyer des
commentaires**, ou ouvrez [Envoyer des commentaires sur WarrantyApp](https://github.com/jaytarr/warrantyapp-feedback/issues/new?template=tester-feedback.yml).

Indiquez approximativement l’heure du problème, ce que vous tentiez de faire et
ce que vous avez vu. Les rapports sont publics et nécessitent une ouverture de
session GitHub. N’incluez aucun identifiant, code d’ouverture de session,
adresse de domicile, contenu de dossier, photo, document, reçu ni renseignement
de paiement. L’équipe du projet connaît déjà la version qui vous a été fournie
et établira le lien à l’interne.
